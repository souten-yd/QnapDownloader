# UI/UX・処理の全面見直し（v0.1.33 で実装済み）

v0.1.12〜v0.1.30で機能を段階的に追加した結果、設定の節が10個に増え、説明文や重複した表示、タイマーやAPI呼び出しが積み重なった。本書は全画面の監査結果と方針。

## 1. 監査で見つかった問題
- 設定の節が10個（エンジン/アカウント/NASブラウザ/保存先/HTTPS/iPhoneから送る/ブックマーク/更新/診断/このアプリ）を横スクロールで並べており、目的の設定に辿り着きにくい。
- ほぼ全節に複数行の説明文。画面の半分以上が説明で埋まる（NASブラウザ、保存先、iPhoneから送る）。
- チェックボックス＋長文の組合せが多く、操作対象と説明の対応が分かりにくい。
- 保存先の「選ぶ」→フォルダ一覧→「閉じる」が画面内に展開され、何を選んだ状態か分かりにくい。
- リンク画面: 空の状態でも「履歴を削除」「未送信のリンクも削除」が常に表示される。
- 同じ状態を複数箇所で取得している（/api/engine/status を6箇所、/api/rb/status を3箇所）。タイマーが34箇所（setInterval/setTimeout）に散在し、画面非表示時の停止条件も個別実装。
- web/app.js が5400行。外部モード（Safari）、旧JSONフレームAPI、3128番の事前診断、MyJD時代の文言など、使われなくなったコードや文言が残っている。

## 2. 方針
### 情報設計
- 設定を **4節** に統合する。
  1. **JD2** — エンジン（状態・主操作1つ）、アカウント、保存先、送信の動作（すぐ開始・長押し自動送信）
  2. **ブラウザ** — NASブラウザ（状態・表示方法・広告ブロック）、サイト別ルール、ブックマーク
  3. **接続** — HTTPS（Tailscale）、iPhoneから送る
  4. **システム** — 更新、診断、このアプリについて
- 旧URL（#/settings/engine など）は新しい節の該当位置へリダイレクトする。

### 表示の抑制
- 説明は1行まで。それ以上は行末の「ⓘ」を押したときだけ開く。
- 設定行はiOS標準の形（左にラベル、右にスイッチや値）。チェックボックスはスイッチに統一する。
- 空のときに意味のない操作（履歴削除など）は出さない。リンク画面の削除操作はヘッダーの「⋯」へ移す。
- 保存先の選択はボトムシートで開き、選んだら閉じる。
- 通知（トースト）は同時に1件まで。同じ種類は件数をまとめて1件に集約する。

### レスポンス・処理の削減
- **状態取得を1本化**: `GET /api/state?since=rev` が、エンジン状態・送信可否・ダウンロード件数・NASブラウザ状態・設定改訂番号をまとめて返す。変化がなければ最大25秒待つロングポーリングにする。画面側はこれ1本で全体の状態を更新し、個別のstatus取得をやめる。
- **タイマーを集約**: 画面に見えている間だけ動く単一のスケジューラに、ダウンロード一覧（5秒）などの周期処理を登録する。非表示・バックグラウンド時は一括停止する。
- サーバー側: docker inspect・JD2設定一覧・アカウント一覧の結果は短時間キャッシュし、同じ要求が重なった場合は1回の取得を共有する。
- 不要コードを削除する（Safari外部モード、旧JSONフレームAPIのうち未使用部分、3128番事前診断、旧文言）。削除前にテストで未使用を確認する。
- 初回表示を軽くする: 設定画面とNASブラウザ用のコードは、その画面を開いたときに初めて初期化する。

## 3. 受入れ
- 全画面（スマホ幅・ライト/ダーク）で、説明文が1行以内、空状態に不要な操作がない。
- ホーム表示後10秒間のAPI呼び出し回数が、見直し前より半分以下になる（ヘッドレスChromeで計測）。
- 既存のテストはすべて合格し、削除した機能のテストは削除または置換する。安全上の不変条件は変更しない。

## 4. 実装結果（v0.1.33）
- 設定は4節（jd2 / browser / connection / system）＋節内の小見出し。旧URLはすべて新しい位置へリダイレクト（`SETTINGS_REDIRECTS`）。
- `GET /api/state?rev=N&wait=S[&full=1]`（管理者認証）。サーバーは engine(2秒)・JD2件数(5秒)・NASブラウザ(2秒) のキャッシュから組み立て、内容が変わると `rev` を増やす。書き込み系のPOSTはキャッシュを捨てて待機中のロングポーリングを即時に起こす。
- 周期処理はスケジューラ1つ（ダウンロード一覧5秒・自動ライブの確認・速度表示・確認中表示）と状態ループ1本。画面が非表示の間は両方止まる。
- **計測（ホーム表示後10秒、仮想時間・スタブDOMでapp.jsを実行、エンジン稼働中を模擬、`tests/home_budget.js`）**: 見直し前(v0.1.30) 7回（health, session, bookmarks, status, settings, downloads, accounts）→ 見直し後 3回（session, state?full=1, state ロングポーリング）= 57%減。ヘッドレスChromeでの計測は未実施（このリポジトリのテストはnodeのみ）。
- app.js: 6093行 → 6143行（設定の4節化・状態ループ・スケジューラの追加分が、削除した個別ポーリングより多い）。NASブラウザ内部は触っていない。
