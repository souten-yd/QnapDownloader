# QnapDownloader — JDownloader 2 + 安全Webブラウザ統合

**詳細仕様書 / v1.1 (設計基準・未実装)**  
対象: QNAP TS-253Be、QTS 5.x、x86_64  
作成日: 2026-11-01  
状態: 実装前仕様（外部サービスと実機の互換性・性能は検証が必要）

## 0. 目的と優先順位

JDownloader 2（以下 JD2）の安定したダウンロード管理を利用しつつ、ブラウジング、リンク検出、Click'n'Load (CNL) 取り込み、保存先管理、進捗閲覧を、1つのQPKG Webアプリで行えるようにする。特にRapidgatorリンクを検出し、手動または明示的に許可したルールで自動投入・自動ダウンロードする。

非機能要件の優先順位: **安全性・データ永続性 > 正確なダウンロード制御 > サイト互換性 > 低ディスクI/O > 省メモリ・使いやすさ**。パフォーマンスのために保存データの破損・欠落やセキュリティ低下を許容しない。

本仕様は、サイトのアクセス制御、認証、ダウンロード制限、CAPTCHA等の不正な回避を目的としない。ダウンロード対象は利用者がアクセス・保存する権利を持つものとする。

## 1. 対象と制約

- TS-253Be: Intel Celeron J3455 (x86-64, 4コア)、RAM 2GB/4GBモデル、最大8GB。RAM実装量は実機で確認し、自動的に機能を制限する。
- QTS 5.x上のQPKGとしてインストール、開始・停止・再起動・アップデート・アンインストール。Docker/Container Stationは必須にしない。
- 既存のJD2がDockerや別のQPKGで稼働している場合、可能なら**既存エンジン接続モード**を提供。別インスタンスを無断起動しない。新規導入時は独立したヘッドレスJD2を管理するモードを提供。
- Web UIはPCおよびiPhone Safari対応、タッチ操作・レスポンシブ。
- ブラウザ機能の成立限界: 単純なiframeでは外部サイトの表示やリンク取得が制限される。Webアプリ単独では外部サイトDOMに無条件にアクセスできない。ブラウザのモード分割を採用する。

## 2. 製品全体構成

```text
PC / iPhone Safari
   | HTTPS (LAN / 任意のVPN)
   v
QnapDownloader Web UI
   +-- ダウンロード管理・検索・設定・履歴
   +-- 軽量ブラウズ（安全リーダー / リンク抽出）
   +-- 対話ブラウザ（必要時のみ起動する隔離ブラウザ）
   +-- 通常ブラウザ連携（共有メニュー / 拡張機能 / URL取り込み）
   |
   v
認証付きAPI / ポリシーエンジン / リンク正規化・重複排除
   +-- 広告・追跡・悪性サイト・遷移制御
   +-- URL/ドメイン/拡張子/権限のダウンロード判定
   +-- CNLリンク取り込み / サイト別ルール
   +-- イベント・状態管理 / SQLite / 最小I/Oログ
   |
   v
JD2アダプタ（正式API優先; バージョン差異検出）
   +-- 既存のJD2への接続、または管理対象JD2の起動
   +-- LinkGrabber / Downloads / Host Account / CAPTCHA
   |
   v
指定の永続ダウンロード先（HDD / ユーザー選択のSSD）
```

隔離ブラウザは主アプリと別権限のプロセス。リモート画面方式の場合、キー操作・画面転送に専用認証を設け、プロセス起動前に空きRAM・CPU・同時利用数を検査する。

## 3. ブラウザ仕様

### BR-01 軽量ブラウズ（通常時）
- URL入力・戻る/進む・再読み込み・履歴・検索・ブックマーク・フォルダ・お気に入り登録・ブックマーク検索。
- サーバが安全に取得可能な公開HTMLについて、本文・リンク一覧を最小表示。広告・トラッカー・第三者スクリプトは原則実行しない。
- 動的サイト/認証サイト/Cloudflare保護サイトでは取得失敗や表示崩れを正常な状態として検知し、対話ブラウザ・端末の標準ブラウザへ切り替える。
- 非信頼サイトのHTMLをQNAP管理画面と同じoriginのスクリプトとして実行しない。表示はサニタイズされた専用ビューか隔離コンテキストとする。

### BR-02 対話ブラウザ（必要時）
- Chromium系の実ブラウザエンジンを用いた別プロセスの対話閲覧（画面転送をWeb UI内で表示）。単一タブを標準とする。複数タブはRAM条件に応じて許可。
- 入力・スクロール・選択・戻る・ダウンロードリンク抽出を提供。サイトの標準TLS検証を維持し、不正な証明書の黙認は禁止。
- セッションはorigin単位で分離。プロファイルの共有・別ユーザーへのCookie転用禁止。認証Cookieの保存はユーザー設定による。
- ページ内ボタンの自動クリック、CAPTCHA自動回答、サイト側のアクセス制限を破るプロキシ・UA偽装は禁止。
- Chromiumの更新・セキュリティ保守は必須。古いエンジンを固定しない。実機で起動性能と互換性を測定し、RAM不足時は起動を拒否して通常ブラウザ連携へ切り替える。

### BR-03 標準ブラウザ連携（高互換性）
- iPhone Safariで開いたURLを共有メニューや「URLを貼り付け」でアプリに送る動線を用意（iOSショートカットはオプション）。
- PC向けブラウザ拡張は後続段階に用意可能。通常ブラウザ内の実DOMからユーザー指示または権限付き規則によってリンクを収集し、認証付きNAS APIへ送信する。
- Cloudflare等で対話ブラウザが動かないときの公式なフォールバック。Webアプリが別originページのDOMを直接読み取れるとは主張しない。

### BR-04 ブラウザの便利機能
- ブックマーク・フォルダ、検索、最近閉じたページ、前回タブの復元（設定可）、タブの簡易グループ化（メモリ条件あり）、URL共有。
- ページ内リンク検出数のバッジ、Rapidgator等のボタン強調、リンク一覧、全選択/選択解除/重複除外、選択分の取り込み。
- ブックマーク単位・サイト単位で自動収集設定を保持。ブラウザ全サイト一律自動ダウンロードは不可。

## 4. リンク収集・Click'n'Load・自動ダウンロード

### LK-01 検出
- 初期の対象ホスト: Rapidgator（ホスト名・URLパターンはプラグイン設定で更新可能）、JD2が対応するその他のホストは汎用リンク判定。
- アンカー、利用者がクリックしたリンク、明示的なCNL要素、動的に出現したDOM内のリンクを安全な範囲で収集する。
- iframe/Shadow DOM/難読化ページ内のリンクは収集可能性に限界がある。リンクなし状態と技術的取得不能状態を区別して表示する。
- URL正規化・重複排除、リンク元URL記録、ホスト識別、未確認URLは審査待ち。
- リンク本文やパスワードは設定された安全な保存ポリシーで扱い、ブラウジングの診断ログに生URL・認証トークンを書かない。

### LK-02 CNL
- CNL2のプレーンリンク/対応コンテナをユーザー操作から取り込み、JD2のLinkGrabberへ渡す。
- CNL2は原来`127.0.0.1:9666`にPOSTする方式であり、端末のlocalhostはNASのlocalhostではない。Webアプリは独自の認証付きNAS APIへ正しく橋渡しする。localhostポートをLANに無認証公開しない。
- サイト固有の暗号化コンテナや互換性差異は、JD2連携と実サイトテストに基づき順次対応。非対応時はURL貼り付け/公式MyJDownloader拡張で代替。
- JD2側での解析・リンク抽出後、ファイル名・容量・オンライン状態・要認証/要CAPTCHA状態を表示する。

### LK-03 自動収集・自動開始ポリシー
- 初期値: **自動開始OFF**。利用者がサイト/ブックマーク単位で「このサイトでRapidgatorリンクを自動ダウンロード」を明示的に許可した場合のみON。
- ルール条件: 閲覧ページのorigin、許可した対象ホスト、リンク形式、リダイレクト先、安全判定、重複、最大リンク件数。検証後は許可した対象に限りJD2へ投入して開始。
- 自動実行の許可例: `(origin = 登録した信頼サイト) AND (最終リンクホスト = Rapidgator) AND (安全性判定=許可) AND (上限内)`。
- 既定の1ページ最大自動投入件数: 20（設定可、上限100）。上限超過は確認待ちにする。
- 広告枠・hidden DOM・勝手に開いた別タブ・自動遷移先・第三者によるスクリプト生成リンクは自動開始対象から外す。
- 既存ファイルは二重登録しない。再ダウンロードは明示的な操作が必要。
- 「リンクを探す」「全て追加」「選択分追加」「自動開始」「監視一時停止」をそれぞれ独立した操作として提供。
- ページ遷移を伴わない動的追加リンクは短時間のdebounceでまとめて判定。無限追跡や無制限のサイト巡回は禁止。

### LK-04 取得失敗
- 無効URL、オフライン、ホストのレート制限、認証切れ、Cloudflare challenge、サイト規約上の制限、プレミアムアカウント不足、保存先不足、JD2未接続を別個に表示。
- リトライは指数バックオフ+上限・一時停止・手動再試行。失敗ループでHDDへ大量ログを出さない。

## 5. 広告・マルウェア・異常遷移の防御

### SEC-01 ネットワーク遮断
- 更新可能な信頼できるフィルターを利用した広告/トラッカー/既知悪性ドメインブロック。HTTPS証明書検証は常時有効。
- サードパーティスクリプト、フィンガープリント用途の既知追跡先、悪意あるポップアップ、通知要求を既定で禁止。単に広告を隠すだけでなく接続自体を抑止する。
- フィルターはメモリに展開し、更新は定期的（既定24時間に1回、変更時のみ永続化）。オフライン時は直近の検証済みデータを使う。
- 認証に必要なファーストパーティやCloudflare公式チャレンジ用リソースは、安全性を検査したうえで誤検知防止の限定例外を認める。サイト全体のフィルター解除は既定で許可しない。

### SEC-02 遷移/ポップアップ防止
- `window.open`、新規タブ生成、外部アプリ起動、通知要求、クリップボード書き込み、フルスクリーン要求、権限取得をポリシーで制御。
- ユーザー操作のない新規タブ・リダイレクト連鎖は遮断。明示クリック後の正常なサイト遷移は許容。正当な認証画面は理由・遷移先を表示して確認後に許可。
- ブラウザ内でダウンロードを勝手に開始する機構は無効化し、全ファイル保存をQnapDownloaderの検証済みJD2キューへ集約する。
- 偽のダウンロードボタン・危険な別ホストへの誘導を検出して警告。誤検知・未知の脅威があり得るため「完全防御」は保証しない。

### SEC-03 サーバ・QNAP保護
- アプリは非rootの専用ユーザー。JD2・ブラウザ・APIは権限を分離。書き込み可能な範囲を専用データディレクトリと許可されたダウンロード先に限定。
- URL取得はSSRF対策を行い、loopback、link-local、NAS内管理サービス、メタデータIP、プライベートアドレス、IPv6ローカル、DNS rebinding、redirect先の再解決を検査し、管理対象内の明示的な例外のみ許可。
- アクセスはHTTPS（信頼できる証明書/リバースプロキシまたはVPN）+管理者認証+セッション期限+CSRF防御。LAN内でも無認証アクセス禁止。初期設定ではインターネットへポート公開しない。
- CookieはSecure/HttpOnly/SameSite属性、秘密情報は安全な保存領域へ。保存する場合は適切に暗号化、復号鍵とデータの権限分離（root侵害への完全な保護とは別問題）。
- ファイル名の正規化、パストラバーサル、シンボリックリンク脱出、ZIP Slip、圧縮爆弾、サイズ詐称を対策。実行可能ファイルは初期状態で自動実行・自動解凍禁止、必要に応じ隔離/マルウェアスキャン。
- 管理APIはレート制限・監査・入力検証・権限検査。サイト側がNAS管理APIへアクセスできないネットワーク/ブラウザ境界を維持する。

### SEC-04 管理者設定
- ブロック履歴（RAMリングバッファ）、許可例外リスト、セッション/Cookie削除、サイト権限リセット、疑わしいリンクの隔離、フィルター更新状態、セキュリティ自己診断。
- 例外の登録は対象origin・必要なリソース・有効期間を限定し、理由を表示。Cloudflareを理由としたサイト全体の無制限許可は禁止。

## 6. Cloudflare/認証サイト互換性

- JS検証は、正規にブラウザが実行する標準的な検証を許可する。Turnstile/Managed Challenge等の人間操作はユーザーが行う。
- チャレンジ用の正規スクリプトを広告ブロッカーで誤遮断しないよう、限定的な例外を管理する。
- HTTPで取得したHTMLを再ホストしたり、チャレンジをcross-origin iframeへ差し替えたりしない。
- 解決操作は原則、同一の正規ブラウザ/ネットワーク経路内で完了。Cookieを別IP、別ブラウザ、別ユーザーに転送しない。
- Chromiumの実ブラウザモードでも、サイトが自動化/埋め込み環境を拒否する場合がある。検証を偽装して回避しない。最新Safari/Chromeの通常閲覧へ誘導し、URL共有/ブラウザ拡張でダウンロード連携を継続。
- チャレンジ成功/失敗/期限切れ/サイト側のアクセス拒否を状態表示。Cookie有効期限・ログアウト要求に従う。

## 7. JD2機能対応

### JD-01 基本機能
- リンク追加（URL/CNL/DLC等JD2対応形式）、LinkGrabber、パッケージ管理、取得進捗、速度、容量、接続数、待機・エラー、開始/停止/一時停止、再開、削除、名前変更、保存先変更。
- 再接続、ホスト制限、同時数、帯域制限、スケジューリング、パスワード付きファイル、アーカイブの扱い、ホストアカウント、CAPTCHAユーザー対応（エンジン提供機能とバージョンに依存）。
- ダウンロード自体はJD2に委任し、アプリは別のダウンローダーを並列実装しない。ホスト側の無料・有料制限を無視しない。
- UIが閉じていてもJD2はダウンロードを継続。ダウンロード状況は権限付きAPIから取得。

### JD-02 推奨設定ワンクリック
- ボタン名「推奨設定を確認して適用」。適用前に現在値と変更予定値の差分表示・バックアップ・確認・適用後検証・ワンクリック復元。
- 既定プリセット「TS-253Be / 静音・低I/O」: 対象ホスト同時1、ファイル同時1〜2、チャンク1（サイト条件が許す範囲）、帯域上限なし（任意）、定期的状態更新を間引く、不要な詳細ログを抑止。
- 無条件に全設定を書き換えない。JD2 Advanced Config APIの存在・型・許容値を照会し、互換性が確認できたキーだけ変更。ホストプラグイン設定は別途検証。
- 外部管理のJD2では既定は「提案のみ」。明示承認なしに既存設定を変更しない。
- 現行のJD2更新を無条件に止めたり、署名・証明書検証を無効化しない。

### JD-03 エンジンモード
- **接続モード**: 既存JD2の正式API/MyJDownloader等のサポート済み経路で接続し、権限と接続状態を検査。外部エンジンの停止/再起動は無断実行しない。
- **内蔵モード**: Javaランタイムの適合性確認、ヘッドレス起動、PID管理、停止時の正常終了、更新後の再起動、異常終了時バックオフ、ローカル管理ポートの限定公開。
- 同一ダウンロード先を複数エンジンが競合利用しないよう警告。既存コンテナを削除・変更せず併用可能性を検証。

## 8. 低ディスクI/O・データ保護（最重要）

### IO-01 永続化の分類

| データ | 保存場所/方式 | タイミング |
|---|---|---|
| ダウンロード本体、途中ファイル | 指定の永続ストレージ | JD2により逐次保存（必須） |
| 確認済みキュー、リンク追加操作 | SQLite等の永続DB + JD2実状態 | 操作確定前に記録 / 二重実行防止 |
| ブックマーク、サイト別ルール、保存先、設定 | 永続DB | 変更時に確実にコミット |
| アカウント/許可されたログインセッション | 制限付き永続領域（任意） | 作成・更新・削除時に保存 |
| 進捗表示、速度、接続状態 | RAM | 通常は保存しない。UI復帰時はJD2の実状態と同期 |
| 広告ブロック統計・直近イベント | RAMリングバッファ | 重大イベントのみ記録。診断エクスポート時は利用者指示で保存 |
| ブラウザ一時HTML/画像/CSS | メモリキャッシュ（上限） | HDDには原則書き込まない |
| 検証済みフィルタ/バージョン | 永続領域 | 新版への変更時のみatomic更新 |
| エラーログ | サイズ/期間上限付き永続ログ | 要点のみ・バッチ化。障害の根拠は保持 |

### IO-02 書き込み削減
- SQLiteには変更差分のみ書く。進捗ポーリング結果を毎回DBへ記録しない。重要なキュー追加・設定変更は即コミット。
- 任意の低重要度操作は短時間（例: 5〜30秒）バッチ化。ただしクラッシュで失ってはいけないイベントはバッチを待たない。
- DBはWALなどの耐障害性のある方式を構成し、チェックポイント・vacuum・バックアップはアイドル時/必要時に限定。DBをネットワーク共有上に置かず、ファイルシステム特性を確認する。
- DBの同期を無効化する、JD2の状態保存を禁止する、ダウンロードをRAMだけに持つなどの危険な最適化は禁止。
- 詳細ログは既定OFF、通常ログはローテーション/レート制御/同一エラー集約。JVMやJD2固有ログ設定はサポートされる範囲で調整。
- 同じファイルの繰り返し全走査、不要なサムネイル生成、毎秒のバックアップ、無駄なフォルダポーリングは禁止。監視はイベント駆動中心。
- ブラウザのプロファイル/HTTPキャッシュは原則RAM上。認証永続化が必要な最小データのみディスクへ。tmpfsが不足した場合、無断でHDDへ退避しない。
- ダウンロードのチャンク数を抑えてシーク・同時更新を減らす。ディスクI/Oと転送性能を比較してホスト別に最適化する。完了ファイルを再ハッシュする場合は必要性と追加読み込み量を明示する。

### IO-03 RAM管理と性能
- メモリ量は起動時に検出。2GB環境では軽量モードを標準にし、対話ブラウザが安全な余裕メモリを確保できなければ起動しない。
- 4GBでも隔離ブラウザは必要時のみ起動し、タブ数1を標準。8GBの場合は環境に応じ拡張。
- API/DB/フィルタにはRAMキャッシュの上限を設け、OOM時にはブラウザを先に終了し、JD2のダウンロード/永続化を守る。
- 以下は性能試験後に調整する**暫定目標**であり、事前の実測保証ではない: アイドル時アプリ固有の不要なディスク書き込みを基準比90%以上削減、UIの状態反映は稼働時2〜5秒程度、ブラウザ停止時にスワップ多発を生じさせない。
- 利用者が設定した保存先のデータ書き込み・ext4等のジャーナリング（jbd2）は正常な処理でありゼロにはできない。書き込み削減はデータの健全性を損なわない範囲。

### IO-04 障害復旧
- 停電・kill・QTS再起動時に、ブックマーク/設定/確定したダウンロードキューを再現できる。
- JD2を起動後、ダウンロード一覧とDBを照合し、不一致は「復旧待ち」として安全に再同期。リンクを重複投入せず、既存ファイルを上書きしない。
- 書き込み不可/容量不足の場合は明示的なエラーを出し、新しいダウンロードを開始せず、既存の安全な状態を維持。
- アップデート前に小容量の設定/DBバックアップを取り、スキーママイグレーションは後方互換/ロールバック可能な範囲で実施。

## 10. API/内部データモデル

### 10.1 内部API（設計上の論理インターフェース）
- `GET /api/v1/status`: 実行環境、JD2接続、稼働メトリクス。
- `POST /api/v1/links/inspect`: URL等の静的検証、抽出されたリンクのプレビュー。
- `POST /api/v1/links/import`: 選択した正規化リンクを冪等キー付きで永続キューへ登録。
- `POST /api/v1/cnl/import`: 権限付きCNL2投入（対応形式のみ）。
- `GET /api/v1/downloads`: JD2が権威ソースの一覧、キャッシュ付き。
- `POST /api/v1/downloads/{id}/action`: start/stop/pause/retry等の権限検証済み操作。
- `GET/POST/DELETE /api/v1/bookmarks`: ブックマーク管理。
- `GET/PUT /api/v1/site-policies`: origin別の自動収集・自動開始ルール。
- `GET /api/v1/security/events`: RAM内の遮断イベントの表示。
- `POST /api/v1/settings/preset/preview`, `/apply`, `/rollback`: 推奨設定操作。
- `GET /api/v1/diagnostics/io`: プロセスI/OとデバイスI/Oの区別を含む観測結果。
- イベント配信は認証付きWebSocket/SSE。断線時は差分取得/再同期。APIの認可はユーザー・操作単位。

### 10.2 永続データ
- `settings(key, value, revision, updated_at)`
- `bookmarks(id, folder_id, title, url, created_at, updated_at)`
- `site_policies(id, origin, target_hosts, auto_collect, auto_start, max_links, enabled, updated_at)`
- `link_intents(id, idempotency_key, source_url, normalized_url, host, status, jd_job_id, created_at, updated_at)`
- `download_metadata(id, jd_package_id, jd_link_id, user_tags, last_known_state)`（JD2が本体、重複保存を避ける）
- `credential_refs(id, host, secret_ref, updated_at)`（パスワードを平文で入れない）
- `settings_backups(id, created_at, diff, snapshot_ref)`
- `audit_events(id, action, actor, outcome, time, redacted_details)`（重要項目のみ、保持期限あり）
- 変更操作には冪等性キー・一意制約・トランザクションを用いる。バックグラウンドの再照合は必要時のみ。

## 11. QPKG要件

- QDK `qpkg.cfg`、QPKG service script（`start/stop/restart/status`相当）、QTS Web UIリンク、サービスPIDと実稼働の整合、ログローテーション、シグナル処理。

- 設定/DBは更新で消えない永続データ領域。実行ファイルとユーザーデータを分離。
- パッケージ配布はx86_64用。内部のJava/ブラウザのバージョンと脆弱性管理、SBOM、チェックサム、ライセンス記載を必須にする。
- 自動アップデートは署名/ハッシュ/互換性検証とロールバックに対応。インストーラは既存JD2やDockerの構成を破壊しない。

## 16. 確定した追加要件（2026-11-01、前章の記述より優先）

- 保存は**フラット**を既定とし、パッケージ名/サイト名/日付/リンク元ページ名ごとのサブフォルダを作成しない。JDownloader一般設定とPackagizerの両方を検査する。UI上のパッケージ分類は維持する。
- LinkGrabberの自動確定/自動開始、ブラウザの自動収集、全サイト自動ダウンロード、自動解凍、解凍後元ファイル削除、完了ファイル削除は初期値OFF。安全なサイト単位でユーザーが明示許可した自動処理のみ例外。
- 保存先は**サーバ側のNASフォルダ選択ダイアログ**から選択し、共有フォルダ/権限/マウント/容量/シンボリックリンク越境を検査して確定保存。QPKG更新・NAS再起動でも保持。変更時は新規ジョブにのみ適用し、既存ダウンロードは移動しない。
- ZIP/CBZ/RAR等は元のアーカイブのまま保存。未完了partは処理対象外。QnapExtractor等への自動処理連携は正式API検証後に設計する。名前を勝手に変更したり上書きしたりしない。
- 安全性: 広告、マルウェア、意図しない遷移/ポップアップ、無断ダウンロードを多層防御。Cloudflare等は正規の認証が必要な場合のみ同じ正規ブラウザで手動完了。不正な回避はしない。
- 重要設定/キュー/ブックマーク/ファイルは確実に永続化。進捗や広告ブロック統計はRAM。ファイルシステムジャーナルやDB同期は無効化せず、低I/Oと保存の確実性を両立。
- 推奨設定はpreview/diff/backup/apply/readback/rollback。JD2の実バージョンを調べずにAdvanced設定キーをハードコードして書き込まない。既存の外部管理JD2は初期は読取専用。
- GitHub: main変更はPR必須、PR作成は書込権限あるコラボレーター/管理者に制限する（別途GitHub側の適用・検証が必要）。QnapSelfCareのルールを参照。

詳細: storage-and-presets.md、security.md、implementation-plan.md、../DEVELOPMENT_WORKFLOW.md、github-protection.md。

## 17. JD2単独更新と設定復旧（追加確定要件）

JDownloader 2はJD2の標準更新経路で単独更新し、QnapDownloader Hubの自己更新とは独立させる。JD2のCore/プラグイン更新後、Hubの推奨設定ボタンから設定の実際の差分を確認して再適用可能とする。適用時は一般設定とPackagizer、LinkGrabber自動開始・確定、自動解凍を独立に確認し、既存キューや完了ファイルを変更しない。詳細: [JD2独立更新と再適用](jd2-independent-updates.md)。認証済みJD2接続がまだ未実装なので現MVPのボタンは無効とする。
